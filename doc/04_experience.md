# 界面、交互、语音与启动设计

## 1. 页面与主要流程

启动 → 配置检查 → 首次创建朋友（已有库则跳过）→ 大厅选择人数/规则 → 阵容预览 → 开始 → 身份私密提示 → 夜间/白天 → 终局 → 复盘/下一局。规则和身份确定后不得在局中修改板子。

大厅显示人数（6–14）、角色计数、是否警长、屠城/屠边、女巫不可自救、狼人无私聊、最后一神猎人仍可开枪、30 日和局上限；这些属于会影响选择的规则。默认 12 人；允许真人指定身份练习；查看朋友姓名与公开外貌，但不展示 AI 内部能力数值。高级设置提供端点、模型、能力、预算与文本速度，Key 不展示明文。

主窗口建议最小 1000×700，可缩放，内容由以下区域组成：

- 顶栏：局号、日数、公开阶段、暂停/继续、设置、帮助。
- 中央约 70% 宽：时间顺序历史、主持词、发言、公开票型与技能结果；保留局内所有本人可见历史，按日折叠与查找。
- 右侧约 30% 宽：固定座位顺序卡片，显示姓名、存活/出局、公开角色证明、警长标记；自己的真实身份单独在“我的身份”区，不能把所有人的 roleId 放入 DOM。
- 底部动作区：当前合法目标和按钮；轮到真人才启用文本输入或对应技能。

视觉颜色示例：主持词蓝、玩家发言常规文本、私人技能结果紫、公开结果橙、错误红。每种同时有“主持人/发言/仅你可见/结果/错误”文字标签，不能仅靠颜色区分。本人私密事件可在主历史展示，但明确标注仅本人可见；“完整历史”指本人完整视野，不等于全局全知历史。

人物弹窗显示姓名、稳定外貌、衣着、局前疲态和最近一次已经公开的神情，注明“表现可刻意伪装”。不显示智力值、真实游戏身份、私有模型观点、夜间闭眼时的动作。隐藏事件也不出现在搜索结果、通知、标题、缩略图和复制功能中。

## 2. 各动作的 UI 契约

| 窗口 | 展示 | 真人提交 |
|---|---|---|
| 狼人夜间投票 | 同伴座位；所有存活目标；自己的锁票状态 | 点击目标或空刀，再确认；不见同伴票 |
| 预言家查验 | 合法存活他人；自己的历史查验 | 选择/跳过；结果仅本人可见 |
| 女巫用药 | 剩余药量；合法刀口提示（若解药在）；救/毒/不用 | 模式互斥，毒需目标；不能自救，不可救时解释理由但不透露其他身份 |
| 发言/遗言/PK | 当前轮次和字数限制，输入草稿 | 文本提交或跳过；自爆仅狼人自己的常规讨论窗口显示 |
| 放逐投票 | 合法候选，自己的票权 | 点击目标或弃票；结束统一公开 |
| 警长竞选 | 上警/不上警，后续退水或保持 | 同步窗口锁定选择，名单结算后发布 |
| 警长方向 | 顺时针/逆时针 | 点击一种 |
| 警徽处置 | 合格接徽座位或撕徽 | 点击确认 |
| 猎人死亡技能 | 当前存活他人和不开枪 | 点击确认；提示只能一次 |

原始需求中的“平按钮”含义不清，本设计按“可点击的动作/目标按钮”解释，不据此发明“平”技能。人物详情点击与选择技能目标是两个不同入口，避免点开弹窗就提交票。目标选择高亮但不生效，确认才锁定。无合法目标时仅显示跳过，并说明资格。不可逆技能确认框展示座位/姓名与效果，不加入全知胜负预测。

所有提交按钮在请求中禁用；重复点击只发同 commandId。拒绝过期动作时刷新视图、保留发言草稿，提示“阶段已变化”；不自动把旧目标套入新阶段。玩家发言中写“我要毒3号”只是一段话，只有女巫合法按钮能产生毒药动作。

AI 等待显示通用阶段等待与暂停入口，不能显示闭眼者看不到的决策身份；单次网络错误先后台重试，达到暂停条件显示去敏通用提示。真人夜间无资格时只能看固定主持指令与过场，不出现谁正在操作。真人死亡后能快进已授权记录、暂停或等待终局，不可继续发言/投票（规则遗言及猎人窗口除外）。

## 3. 文本播放和未来语音

引擎事实提交与 UI 阅读进度分离，但必须在所有应呈现给下一发言者的公开事件完成后才开下一个决策窗口。无人能投票同时看到未来未播放发言。

初始设计 TextPresenter 默认 6 个汉字/秒；后续用户反馈后，当前默认立即显示，不再为未来语音减缓刷新（见[更新记录](10_llm_backend.md)）。可选阅读动画，提供 3/6/12 字每秒及“立即显示”；按字符分段，不按 token 流显示。选速只是阅读辅助，不代表已测量的人类语速；超长段落允许立即显示。单段播完才推进下一轮，真人可点击“读完了”跳过打字效果。历史一旦接受就完整存储，当前段只是呈现动画；查看该段全文可视为立即完成当前段。

Presentation 契约：`present(event, options) → completion`；completion={eventId,status:finished/skipped/cancelled}。暂停停止定时器，继续从字符进度恢复；用户滚动到旧记录不自动前进当前段；自动滚动可关闭，新消息以未读标记提示。

预留 `SpeechOutput.synthesize({text,voiceProfile,signal}) → {audioRef,segments}`、`play/pause/resume/stop`，以及 `SpeechInput.start({language,signal}) → draft`。voiceProfile 只取人格合法语音参数，不包含身份/密钥；默认没有供应商实现，不调用语音服务。未来 TTS 完成事件取代阅读定时器作为推进信号，字幕以音频时间戳同步；失败回退文字，并明确提示。用户跳过音频需 stop 后 finish，防止下一人讲话时旧语音仍播放。

ASR 将识别结果放入真人草稿，必须真人确认后提交；技能仍按按钮操作。未来语音供应商独立配置和权限提示，不默认把所有历史发给语音服务。首版无麦克风采集需求，不显示空洞不可用的语音按钮。

## 4. 暂停、退出与异常

暂停：关闭新窗口调度、取消在途模型请求、冻结播放，已提交事实不回滚。若某秘密投票已锁定，恢复后保留；未完成请求重新生成。退出：自动保存后关闭，磁盘失败则阻止正常退出并允许用户明确选择不保存退出。启动发现进行中局，默认显示“继续上局/放弃上局”。

菜单：新游戏、初始化朋友、休息一下（仅局间可用）、模型设置、文本速度、查看手册、存档管理、退出。局中“新游戏/初始化朋友”先说明将放弃当前局，再由用户确认；这是产品内破坏性操作确认，不是本次设计工作审批。

终局显示阵营结果、每位真实身份与公开关键动作；真人死亡仍按所在阵营获得输赢。随后生成朋友反思，可后台进行；下一局启动前每人记忆必须完成或写入模板，避免半组人带新经验。复盘中切换全知事实不影响 AI 记忆。

## 5. macOS 一键启动

源需求同时要求 mystery.sh 与 Finder 双击。`.sh` 的双击行为取决于文件关联，不能仅靠扩展名保证启动。因此后续交付同时包含实际入口 `mystery.sh` 和 Finder 入口 `mystery.command`（执行同一脚本）；可在说明中提供将 `.sh` 关联 Terminal 的可选步骤，默认用户双击 `.command`。

启动脚本必须基于自身路径定位应用与 api_key.env，不依赖 pwd；路径含空格/中文需正确引用；设置可执行权限；检查支持的 Node 版本和已安装运行文件。缺依赖时给出明确安装指引，不每次启动自动联网 npm install、不把密钥打印到终端。发布版优先打包 .app，内置运行时；脚本开发入口仍保留。

未签名 .app 可能受 Gatekeeper 限制；正式分发需签名及公证，不能设计为自动关闭安全系统。验收必须在真实 Finder 上测试双击 .command，以及终端调用 .sh；本次没有创建或执行脚本。

## 6. Electron 与配置安全

遵循 [Electron 安全指南](https://github.com/electron/electron/blob/main/docs/tutorial/security.md)与[沙箱文档](https://www.electronjs.org/docs/latest/tutorial/sandbox/)：renderer 使用 nodeIntegration=false、contextIsolation=true、sandbox=true；只加载应用本地资源，CSP 禁止外部脚本和 eval。Preload 仅暴露有限 typed API，不暴露通用 ipcRenderer、filesystem 或 shell。

允许桥接的操作：getLobby、startMatch、getObservation、submitAction、pause/resume、getPersonaPublic、listSaves/loadSave/deleteSave、getSettings/updateNonSecretSettings、testProvider、subscribeViewEvents、getCompletedReview。敏感凭据配置由主进程处理，不在普通 settings getter 返回。

每个 IPC 校验 sender/frame、参数 Schema、game 绑定及允许状态。人类无法通过 review API 访问未终局真相。LLM 和玩家文本按纯文本渲染，禁止 HTML/Markdown 中脚本与任意链接执行；长文本有长度和分页约束。外链只对白名单帮助链接启用系统浏览器，不加载进有桥接能力的窗口。

未来 Git 初始化前忽略：secret/、api_key.env、*.env（保留无秘密的 .env.example）、存档、调试与构建日志。发布和导出使用明确 allowlist，不能仅依赖 .gitignore：忽略不会阻止手工打包或已经跟踪的文件。CI/发布前做凭据模式与高熵值扫描，但不打印疑似密钥本身。配置文件建议只允许用户读写；错误报告不上传默认存档和 prompt。自定义模型端点意味着合法玩家视图将发给该服务，大厅设置需说明此实际数据流。
