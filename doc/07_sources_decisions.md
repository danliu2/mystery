## 2. 关键决策记录

| ID | 选择 | 理由及替代方案 |
|---|---|---|
| D01 | 确定性Host + LLM独立参与者 | LLM主持难以稳定合法性和隔离；纯脚本主持配AI参与者可验收与重放 |
| D02 | main保管全知状态，按seat投影 | renderer拿全量后隐藏易泄漏；每个AI各一完整进程成本过高且仍需投影 |
| D03 | 狼人无夜聊，平票种子随机 | 严格遵守源需求；队长票或公开狼票会额外建立沟通/领袖偏置 |
| D04 | 12人经典角色、10–14人警长 | 完整保留典型玩法；小局省警长避免过长。小局胜率需测量 |
| D05 | 6–7屠城，其余屠边 | 小局只有两神时屠边容易过短；不是官方统一规则 |
| D06 | 女巫永不可自救、每夜单药 | 消除首夜例外歧义，保留自刀骗药策略；可在未来新规则版本加入首夜自救 |
| D07 | 死亡技能先于终局，狼全灭优先 | 降低最后猎人点击尚未出现就终局的困惑；与部分平台先判屠边规则不同 |
| D08 | 白痴自动翻牌，无遗言、留场发言 | 简化不必要动作窗口，避免重复遗言与正式发言；保留经典投票限制 |
| D09 | 事务文件存储，资源快照冻结 | 单机易审计；后续规模需求出现再替换数据库；不假定多文件写入天然原子 |
| D10 | 结构化动作非流式，文字本地播放 | 先校验完整结果可防无效发言与技能；以后流式只在私有缓冲完成验证 |
| D11 | 经验来自本人视角，不来自全知复盘 | 维护非完全信息承诺；全知训练可能有价值，但需要独立实验授权及清楚标注 |
| D12 | AI数值是提示风格，不是认知测量 | LLM服从数值的实际效果未证实，不能保证高数值必聪明 |
| D13 | .sh实际入口 + .command双击入口 | Finder对.sh关联不统一，不承诺单独.sh天然双击执行 |
| D14 | 首版仅文字，统一presentation接口 | 未来TTS接管完成信号而不是改写规则状态机 |

## 4. 待评审的高影响假设

本设计已为实现选定明确默认值，无需实现者临场裁决；以下项目允许评审后以新版本修改：6–7人屠城、10人起警长、首日天亮后竞选、自己的讨论轮次才能自爆、女巫不可自救、最后猎人先枪后判、20人中的性别表达比例、精力更新幅度和每局预算。它们是产品假设，不是未完成的占位符。

规则调整必须同步01、06、JSON契约和05验收案例。人格参数不影响权限；即使改变模型或语音供应商，也不能跳过合法动作、视野投影与持久化事务。
